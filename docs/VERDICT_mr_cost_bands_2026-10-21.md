# 판정 — 커브 MR 의 **「비용 띠」는 계열의 성질이 아니다** [2026-10-21]

> 앞 판(`PROMPT_next_2026-10-21.md` §2)이 남긴 두 가지를 재러 들어갔다:
> ① 경계 계열 둘(`IRF-2Y-3Y-5Y`·`IRF-1Y-1.5Y-2Y`)을 **실가격으로 다시 재기**,
> ② 오너 결정 하나 — **IRS 체결 비용을 반으로 줄이면 무엇이 사나.**
>
> ①은 **할 수 없다**(§1). ②는 답이 나왔다(§4). 그리고 재는 과정에서 앞 판의
> 띠 표가 **두 군데 틀렸다**는 것이 드러났다(§2·§3).

**결론 셋.**

1. **①은 불가능하다.** IRS 커브·플라이에는 실가격 회계가 **아예 없다**
   (`main.py:1797`). 그 둘은 `irf` 다. 엔진 근사의 오차는 **못 줄인다.**
2. **띠는 계열의 성질이 아니다** — 16계열 중 **14**에서 칸에 따라 띠가 갈린다.
   144칸 전부가 한 띠인 계열은 **둘**뿐이다.
3. ★**앞 판의 `FSW-10Y` 한 줄은 격자의 「최악 칸」을 적은 것이다.** 채택 칸으로
   다시 재면 손익분기 배수 **+2.539**, 실가격으로는 **+3.476** — 열여섯 계열 중
   **제일 좋다.** 「비용이 0 이어도 진다」는 **철회한다.**

## 0. 재는 자 — 먼저 못 박는다

| | |
|---|---|
| 손익분기 | `summary.breakevenCostMult` = **지금 가정 비용의 몇 배까지 견디는가.** 1.0 이 본전선 |
| 왜 배수인가 | 손익분기 **bp 자체는 가정 비용과 무관**하다(약분된다 — 앞 판 §2 의 유도). 그래서 비용을 반으로 줄이면 **배수가 그대로 두 배**가 되고, 다시 돌릴 필요가 없다 |
| 가정 비용 | 거래 한 번 **0.5bp**(아웃라이트·커브) · **1.0bp**(플라이 — `mrplan.cost_multiple` 이 한쪽 면 기준으로 2배) |
| 채택 규약 | **1y 격자의 Calmar 1등 · 거래 3건 이상.** 그 노브를 전 표본 격자에서 찾아 읽는다 |
| 기본 칸 | `mrplan.BASE_KNOBS` = L60 · e2.0 · x0.5 · s2.5 · level (격자를 안 돌리면 서는 칸) |
| 격자 | 144칸(전 표본). 「유효칸」은 거래 3건 이상인 칸 |
| 엔진 vs 실가격 | 엔진 = `_mr_optimize` 의 칸(`real: false`) · 실가격 = `/api/mr/strategy` 의 `real: true` |
| 측정일 | 2026-10-21, 라이브 백엔드 `:8200` pid 25904 |

재현: `scripts` 가 아니라 라우트 둘로 끝난다 —
`/api/mr/optimize?id=<계열>&span=1y` 로 채택 칸을 고르고,
`span=all` 에서 같은 노브의 칸을 읽고, `/api/mr/strategy?id=<계열>&<그 노브>` 로

지나 A/B 를 오염시킨다.

## 1. ★①은 할 수 없다 — IRS 에는 실가격 회계가 없다

```python
# backend/app/main.py:1797  (_mr_real_accounting)
if kind not in ("bss", "fut", "fsw"):
    return False
```

| 종류 | 계열 | 실가격 회계 | 무엇으로 가격하나 |
|---|---|---|---|
| `bss` | 국고 자산스왑 | **있다** | `cashbond.book_recon` — 민평 행렬 |
| `fut` | KTB3·KTB10 내재금리 | **있다** | 조정가 차분 + 롤 비용(0.5틱) |
| `fsw` | 퓨처스왑 3Y·10Y | **있다** | 선물 조정가 + IRS 다리 스왑 엔진 |
| `irc` | IRS 커브 여덟 | **없다** | — |
| `irf` | IRS 플라이 넷 | **없다** | — |

실측으로 확인했다 — 여섯 계열에 `/api/mr/strategy` 를 때려 `real` 을 읽었다.
`irc`·`irf` 다섯은 전부 `real: false` 이고, **손익이 엔진 칸과 한 자도 안 갈렸다**
(예: `IRF-2Y-3Y-5Y` 엔진 −14,247,284.35원 = 전략 −14,247,284.35원, 거래 47건 동일).
같은 산술이라는 뜻이고, 그래서 **다시 재도 같은 수가 나온다.**

★**앞 판의 지시 「경계 계열 둘을 실가격으로 다시 재서 생사를 확정하라」는 수행
불가다.** 그 둘은 `IRF-…` = `irf` 다. 오차를 줄이는 길은 **재측정이 아니라
`_mr_real_accounting` 에 IRS 다리를 더하는 것**이고, 그것은 새 작업이다.

## 5. 코드는 한 글자도 안 바꿨다

이 판정은 **읽기만** 했다 — 라우트 둘(`/api/mr/optimize`·`/api/mr/strategy`)에
GET 을 때려 읽은 수다. 엔진·격자·회계 어디도 안 만졌다.

고칠 자리가 하나 있는데 **이 레인의 몫이 아니다**: `_mr_real_accounting` 이
`irc`·`irf` 에서 조용히 `False` 를 돌려준다. 화면은 그 사실을 `real` 로 싣고 있어
거짓말은 아니지만, **「실가격으로 재라」는 지시를 받은 사람이 그것을 모른 채
재고 같은 수를 얻는다**(내가 그랬다). 더 할 일은 §1 의 그 문장이다.

## 6. 다시 열지 말 것

- **「격자를 커브에 돌리는 것이 맞나」** — 앞 판이 끝냈다(격자가 커브에서 14/16
  이김). 이 판정은 그것을 안 건드린다.
- **「손익분기를 비용 가정마다 다시 재기」** — 필요 없다. 배수는 가정에 반비례
  하므로 한 번 재고 나누면 된다(§0).
- **「`FSW-10Y` 를 접기」** — 철회됐다(§3).
- **「경계 계열을 실가격으로 다시 재기」** — 불가능하다(§1). 다시 시도하면 같은
  수를 얻고 `real: false` 를 다시 본다.
