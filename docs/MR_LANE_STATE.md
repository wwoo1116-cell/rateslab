### 창이 화면 밖으로 자라던 자리 [2026-09-02 감사 → `85eef8d8`]

서랍을 `flex-shrink: 0` 으로 둔 것이 지나쳤다. 창을 화면 아래로 끌면 창 상한
(`100vh − top − 24`)이 서랍+머리+탭보다 작아지고, 몸통이 0 이 된 다음에는
**부족분을 물 쪽이 없어** 창이 화면 밖으로 자랐다(실측: 창 하단 948 · 화면 911
— 37px 밖). 0 을 준 근거였던 「서랍 상한 38vh 가 창을 못 밀어낸다」는 **창 상한이
38vh 보다 클 때만** 참이었다.

지금은 0 이 아니라 **비율**이다 — 몸통 `flex: 0 12 auto` · 서랍 `flex-shrink: 1`.
의도(「먼저 주는 쪽은 몸통」)는 그대로고, 기본 위치에서 서랍 332px(49행)로 종전과
같다. 극단(top 780)에서는 몸통 0 → 서랍 16 으로 눌리며 **창은 화면 안에 남는다**.
가드가 두 값을 다 잰다(`guards/mr-canon.test.ts`).

> 교훈: **flex 에서 0 은 「양보 순서」가 아니라 「끝까지 안 줌」이다.** 순서를
> 원하면 비율을 쓴다. 그리고 「A 가 B 를 못 밀어낸다」는 주장은 **B 가 A 보다
> 클 때**를 재 봐야 참이 된다.

### 「관찰 σ」(`warnZ`) 은퇴 [OWNER 2026-09-02 — "이건 뭔지 확인하고 필요없으면 치우기"]

이름은 「경보 문턱」인데 **경보하는 곳이 없었다**. 그 값이 한 일은 z 오실레이터에
±1.5σ 점선 두 줄을 긋는 것뿐이고, 읽는 마커·집계·상태 문장이 화면에 하나도 없었다.
통합 장부 창에는 애초에 없어서 두 창이 갈려 있기도 했다(캐논 얼라인 8). 그림에는

## 6. 다음에 할 것 — 우선순위

**① 국고 다리를 민평 → 체결가로** ⭐ 가장 크다
지금 국고는 **민평(평가사 고시)** 이다. 이 리포의 연구 레인이 «마크는 SR 을

**통합이 생기면서 이 항목이 더 커졌다**: 화면이 이제 «아홉을 같이 치면 SR 1.07»

같이 움직인다.** 옮길 때 `_mr_leg` 한 곳만 고치면 낱개·통합이 같이 따라온다.

**② 다리 수 상한이 없다** [오너 결정 대기]
동일가중 합이라 신호가 나면 **아홉이 다 들어간다** — 실측 최대 동시 9다리
(2016-11-17), 그날 걸린 명목이 900만원/bp 다. 평균은 1.33다리이고 46%의 날은
포지션이 없다. 「한 번에 몇 다리까지」가 정해지면 그건 노브가 아니라 **데스크의
제약**이라 서버가 진다(`allow_dirs`·`TRADABLE_DIRS` 와 같은 자리). 지금은 상한이
없다는 사실을 화면이 「최대 동시·그때 명목」으로 말하고만 있다.

**③ 만기별 명목을 다르게 걸 근거가 보인다** [미착수]
짧은 쪽이 세다는 것은 이미 두 번 나왔다 — 신호일 앞수익(6M +3.75bp ~ 10Y +0.74bp)

안 된다**(격자가 아홉 배로 늘고 DSR 이 그만큼 나빠진다 — §긴 표본 판정 참조).

**④ 계열 축 이웃 칸** [전제가 바뀌었다 — 이웃 칸은 2026-09-02 에 **두 창 다**

`neighbors` 는 노브 넷(룩백·진입σ·청산σ·손절σ)만 보여 주고 전부 같은 계열이라

2. **날짜로 맞춘다.** 만기마다 민평×IRS 교집합이라 표본 날짜가 다르다(실측: 6M·

4. **`_mr_leg` 를 고치면 두 화면이 같이 움직인다.** 그게 이 구조의 목적이다 —

## 문턱은 정확히 지켜지고 있다

「z 값대로 안 하고 마음대로 짠 것 아니냐」는 의심이 있었다. **아니다.**
`BSS-3Y` 거래 15건 전수를 보면 진입은 전부 `|z| ≥ 2.00`, `exit` 는 전부
`|z| ≤ 0.5`, 유일한 `stop` 은 `z = 3.93 ≥ 3.5` 다. 코드도 그대로다:

```python
should_stop = abs(zi) >= stop_z
should_exit = abs(zi) <= exit_z
elif abs(zi) >= entry_z:  want = -1 if zi > 0 else 1
```

## 승률 93% 는 성과가 아니다 — 그리고 「청산=승」도 법칙이 아니다

한 칸(`BSS-3Y·룩백60`)만 보면 «청산 → 승 14 / 손절 → 패 1» 로 대응이 100% 라
동어반복처럼 보인다. **그건 그 칸의 성질이다.** 전 계열 × 룩백 3종(39구성 ·
거래 1,296건):

```
청산 → 승 762   ·   청산 → 패 401      ← 청산의 35%가 손실
손절 → 패 123   ·   손절 → 승  10
```

z 는 **움직이는 평균**에 대한 거리라, 값이 그대로여도 평균이 따라 올라오면
손실인 채로 청산된다. 승률은 구성별로 **11%~100%** 로 흩어지고(중앙값 78%),
100% 다섯은 전부 **6~9건**짜리다 — 승률은 거래 수의 역함수다.

## 스왑만 치는 판은 **기각**됐다

「BSS 를 신호로만 쓰고 실제로는 스왑 페이/리시브만 친다」를 재 봤다. 신호는
BSS, 손익은 IRS 로 갈아 끼운 판이다(엔진과 같은 규칙임을 자기검사로 확인한 뒤
손익 계열만 바꿨다). BSS 아홉 만기 전부:

```
스프레드 매매   합계 +10억 5,045만   SR 중앙값  1.10   양수 9/9   평균 MDD  2,424만
스왑만 페이     합계  −5억 9,215만   SR 중앙값 −0.18   양수 1/9   평균 MDD 1억 6,154만

```

승률이 50%대로 무너지고 낙폭이 **7배**가 된다. BSS 의 z 는 «국고와 IRS 의
관계» 신호이고 어느 쪽으로 좁혀질지는 말하지 않는다 — 한 다리만 치면 신호가
아무 견해도 갖지 않은 금리 방향에 통째로 노출된다(IRS 3Y 가 표본 기간에
128bp → 381bp 로 갔다). 문헌도 같은 방향이다(아래).

## 당일 종가 체결은 **부풀리고 있지 않다**

문헌이 same-bar 체결을 *"the most common concrete form of look-ahead bias"*
라 부르고 징후를 *"too clean — smooth equity, few losers"* 라 해서 의심했다.
신호를 한 봉 늦춰 다시 재니 아홉 만기 전부에서 **오히려 좋아졌다**:

```
당일 종가 체결   합계 +10억 5,045만   SR 중앙값 1.10
다음 봉 체결     합계 +12억 2,200만   SR 중앙값 1.18
```

신호가 60일 z 라 느려서 하루 늦어도 되돌림이 남는다. (볼린저 레인이
「즉시 0.64 → 지연 0.08」로 무너진 것과 다른 이유가 이것이다 — 저쪽은 밴드
재진입이라 엣지가 한 봉 크기였다.)

## 외부 문헌 대조 — 셋 부합, 둘 어긋남

**부합** ① 스왑스프레드는 두 다리 **DV01 중립**이 표준 표현이다(Clarus).
② 문턱 2σ / 0.5~1σ / 3σ 는 관례 그대로다(QuantInsti). ③ 높은 승률 + **음의
왜도**(작은 이익 다수·가끔 큰 손실)는 평균회귀의 서명이다(QuantifiedStrategies).

**어긋남** ④ 평균회귀의 통상 승률은 **50~65%** 인데 우리는 87~93% 다 — 표본과
한쪽 방향 탓이다. ⑤ **전제가 보편적이지 않다**: 미국 30년 스왑스프레드는
2008년 9월 이후 **줄곧 음수**이고, 그 지속성을 연금 듀레이션 수요·딜러
대차대조표 제약으로 설명하는 것이 Klingler·Sundaresan(J. Finance 2019)·
Jermann(2020)·NY Fed 다. 그 문헌의 한 줄이 우리 손절 설계를 겨눈다 —
미스프라이싱이 사라지기 전에 더 벌어져 손실로 밀어낼 수 있다.

우리 엔진은 60일 이동 평균이라 레벨 이동을 따라간다(부분적 방어). 대신 이
거래가 재는 것은 «경제적 균형으로의 회귀» 가 아니라 **«최근 60일 평균으로의
회귀»** 이고, 그건 훨씬 약한 주장이다.

## 캐리 — 중간 현금흐름은 안 상쇄된다

```
BSS −1 = 국고 매수 · IRS 페이 → (국고−조달) + (CD−스왑) = BSS + (CD−조달)
FSW −1 = 선물 매수 · IRS 페이 →     0       + (CD−스왑) = CD − 스왑
FUT −1 = 선물 매수            →     0                   = 0
```

선물에 조달을 붙이면 **이중계상**이다 — 증거금만 걸고 일일정산하며, 채권의
캐리는 선물 가격에 이미 박혀 있고 엔진이 재는 값은 그 가격에서 나온
내재수익률이다. 그래서 부호가 갈린다(조달 = 기준금리+10bp):

```
BSS-3Y 중앙 +0.090%/년   BSS-10Y 중앙 +0.379%/년   FSW-3Y 중앙 −0.092%/년
```

크기는 손익의 **4~11%** 이고, **승률을 93% → 86.7% 로 내린다**(캐리가 음수인
거래가 승패를 뒤집는다). 캐리는 결과를 좋게만 만드는 항이 아니다.

**★ 단위 함정.** 커브(국고·IRS·CD)는 **%**(3.817)인데 `funding.rate_on` 은
**소수**(0.0285)다. 그대로 빼면 100배 틀린 캐리가 나오는데 **예외가 아니라
그럴듯한 큰 수**(중앙 2.667%/년)가 나온다. 대수적으로 BSS 캐리는
`BSS + (CD − 조달)` 로 접혀 0.1% 안팎이어야 한다는 것이 그것을 잡은 자다 —
`mrcarry.assert_identity` 가 두 길로 같은 수가 나오는지 잰다.

**CD 91일은 `mkt_irs_close.cd_rate` 다.** `universe._fetch_irs` 의 매핑에는
6M~10Y 만 있어 3M 노드가 없다 — 따로 읽어야 한다(한 번 헛짚었다).

## 진입 규칙 — 레벨 대 복귀, 전 계열 실측 (2026-08-28)

오너의 「외부로 이탈했다가 다시 그 선을 터치할 때」는 **엔진이 하고 있던 규칙이
아니었다.** 원본 PMS 는 `|z| ≥ 진입σ` 인 모든 봉이 신호인 레벨 검사이고, 밴드를
**뚫는** 봉에 들어간다. 측정 보드(`mr._state`)는 이미 「재진입 n일째」를 판정하고
있었으므로, 두 화면이 같은 사건을 다른 규칙으로 말하고 있었던 셈이다.

둘을 나란히 놓고 전 계열을 쟀다(기본 노브 · 캐리 켬 · 명목 100만원/bp):

```

BSS-3Y      복귀    14   93%        2,777    0.76        900

그래서 판정이 아니라 **노브**로 뒀고, 기본값은 원본 규칙(`level`)이다 — 적합성
벡터가 그 위에 서 있다.

## 승률·과거적합 의심에 대한 답 [OWNER 2026-08-28] — 그리고 화면이 그것을 말한다

오너 질문 둘. 「저렇게 단순한 전략이 승률이 이렇게 높을 수 있나」 · 「과거에
Overfitting 된 것 아닌가」. 둘 다 화면 밖에서만 답할 수 있었으므로 `app/mrdiag.py`
를 만들고 전략 실험 창에 **진단** 절을 세웠다(성과 카드 바로 다음, 이웃 칸 앞).

### ① 롤갭은 v2 계열에 **안 옮겨온다** — 먼저 확인했다

이웃 레인(`Desktopss-xgb`)이 온더런 지표종목에서 지표교체일 |Δ| 3.343bp 대
비롤일 0.825bp(**4.1배**), 최대변동 8일 중 5일이 롤이라고 보고했다. v2 는 같은
BSS 라도 **만기별 커브**(민평 매트릭스)라 구성이 다르므로 실측했다.

```
BSS-3Y   롤일 28건 평균|Δ| 1.730bp · 비롤일 0.820bp · 2.11배 · 최대변동 20일 중 2일
BSS-10Y  롤일 28건 평균|Δ| 1.193bp · 비롤일 0.854bp · 1.40배 · 최대변동 20일 중 1일
손익 기여 −1.3% · 롤일 제외 시 SR 1.60 → 1.63
```

**상수만기 구성이 롤을 안 싣는다.** 옮겨오지 않으므로 조정계열을 만들지 않는다.
(지표지정일은 `infomax.국재지표지정여부` 의 `변경내용 LIKE '%지표지정%'`.)

### ② 승률은 청산 구조의 산물이 **아니다** — 신호가 실제로 일한다

청산 규칙을 떼고 고정 10영업일 보유로만 재면(9계열·긴 표본):

```
신호일(실행 가능 방향)  n=1,364  10일 평균 +2.596bp  적중 76%
비신호일               n≈25,000 10일 평균 −0.130bp  적중 50%

만기별  6M +3.75 / 9M +4.47 / 1Y +4.61 / 1.5Y +3.67 / 2Y +3.37
        3Y +1.84 / 5Y +1.08 / 7Y +0.52 / 10Y +0.74   ← 짧을수록 세다
```

**★ 방향을 빼먹으면 답이 뒤집힌다.** `|z| ≥ 진입σ` 로 세면 BSS-3Y 가 −0.374bp·
적중 47% 로 나오고, 실행 가능한 쪽(`z ≥ +진입σ`)만 세면 **+1.842bp·적중 72%** 다.
못 하는 거래(z ≤ −2σ)의 수익이 섞이기 때문이다. `mrdiag.forward_edge` 는
엔진의 `_entry_signal` 을 그대로 불러 방향을 판정하고, 화면 라벨도 `|z|` 가
아니라 `z ≥ +2σ` 로 적는다(`signalCond`). 테스트가 이 성질을 잰다.

### ③ 승률 93% 의 정체 — 사유별로 쪼개면 보인다

```
BSS-3Y 기본 규칙   청산 14건 승률 93% 평균 +4.02bp · 11.4일
                  손절  1건 승률  0% 평균 −8.02bp ·  1.0일
                  손익비 1.08 · 프로핏팩터 7.00
```

승률만으로는 「작게 여러 번 이기고 크게 가끔 지는」 모양인지 알 수 없다. 손익비가
승률 옆에 없으면 그 승률은 읽는 사람을 속인다.

### ④ 과거적합의 증거는 못 찾았다 — 대신 **엣지 소멸**이 보인다

```
BSS-3Y  2020-01~2022-03  SR 1.15  +1,775만
        2022-03~2024-05  SR 0.88  +2,062만
        2024-06~2026-08  SR 0.42    +607만

## 실측 프로브 — 화면을 «재는» 방법

얼라인 감사에서 쓴 방법이고 이 레인에도 쓸 수 있다. 브라우저 콘솔에서 행마다
컨트롤 높이·라벨 top·이웃 간격을 재고, 접힌 행은 줄마다 따로 잰다. 오늘 그것이
실제 위반 넷을 잡았고 **오탐 셋도 걸러냈다**(고칠 뻔했다). 다만 그 프로브는

## 선물 넷을 실가격 대사로 — 롤일과 롤 비용 (2026-09-04) [OWNER — «0.5틱으로 해두자»]

인계문(`HANDOFF-mr-futures-2026-09-03.md`) §4 의 배선 셋을 실측했다. 하나는
인계문의 전제가 틀렸고, 하나는 새 오너 결정이 나왔다. **아직 코드는 안 바꿨다**
— 이 절은 그 전에 남기는 근거다.

### ① 명목 → 액면 — 식은 이미 있었다

    액면 = (₩/bp) × 100 / synth_pvbp(진입일 벤더 내재금리, FUT_YEARS[테너])

`futures.fsw_swap_leg` 의 `fut_dv01_won` 의 역이다. 이름 붙은 함수가 없어
**정방향만 인라인**으로 서 있으므로 거기서 뽑아 둘이 같은 것을 부르게 한다
(두 번째 정의 금지 — `fsw_swap_leg` 머리의 그 규칙).

100만원/bp 는 3Y 에서 진입일에 따라 31.96~34.98억, 10Y 는 9.67~12.07억이다.
BSS 와 같은 이유로 **거래마다 진입일**에 잰다.

### ② 방향 사상 — FUT 는 −dir, FSW 는 +dir

실측으로 확정했다(각 여섯 거래에서 부호 전건 일치).

- `FUT-KTB3/10` → `FUT:3Y/10Y` **direction = −dir**. MR 값이 금리라
  +1(금리 롱) = 선물 매도다. BSS 와 같은 사상이다.
- `FSW-3Y/10Y` → `FSW:3Y/10Y` **direction = +dir**. MR 값이 스프레드이고
  `futures.py` 의 `+1 = 호가값(스프레드) 롱` 과 같은 말이라 뒤집지 않는다.

### ③ IRS 다리 — **인계문이 틀렸다. 빠져 있지 않다**

인계문 §4-3 은 「`book_recon` 안에 FSW 의 IRS 다리가 있는지 확인할 것, 없으면
합치는 방법이 오너 결정」이라고 적었다. 둘 다 아니다.

- `futures.run_one` 은 `fsw_swap_leg` 로 스왑 엔진(`_run_one`)을 태워
  **캐리·롤다운·개시까지 채워** 돌려준다(실측: FSW-3Y 52거래에서 캐리 20.9백만·
  롤다운 0.7·개시 1.1).
- `futures.book_recon` 만 선물 다리다. 그건 결함이 아니라 **엔진 단위 분리**
  [OWNER 2026-08-25] 이고 모듈 머리에 근거가 적혀 있다.
- 합치는 자리도 이미 있다: `mixedbook.book_recon` 이 `{swap, bond, futures}`
  셋으로 돌려주고 FSW 의 IRS 다리를 **같은 `fsw_swap_leg` 로** 스왑 표에
  합류시킨다(`mixedbook.py:566`). 화면도 있다 — `BacktestWindow.tsx:528~578`
  이 그 셋을 `ReconStack` 세 장으로 그린다.

**그러므로 MR 은 결정할 게 아니라 2026-08-25 결정을 베낀다.**

### ④ 롤 마스크는 실가격에서 **죽는다**

`mrbacktest.py:230` 의 근거 문장은 이렇다:

> 계약이 갈리는 날의 차분을 **아무도 실현하지 못하는** 계열만 그 봉을 0 으로
> 받아 온다

이 문장은 **벤더 내재금리 차분**에 대해 참이고 **조정가 차분**에 대해 거짓이다.
조정가는 그 갈림을 뺀 계열이고 그게 존재 이유다. 회계를 조정가로 옮기면 마스크가
고치던 병이 애초에 없다 — 근사를 정당화하던 문장이 전제와 함께 죽는 그 자리다.

실측이 그 사실을 받친다. 비롤 날에는 조정가 차분과 벤더 내재금리에서 유도한 값이
**3Y 중앙 0.001 가격포인트로 일치하고 0.05 초과가 0건**이다(2,613봉). 어긋나는
것은 롤일뿐이고 어긋나는 쪽은 벤더 값이다(3Y 42 롤일 중 41일).

**시점은 안 바뀐다.** `dv_bar` 는 `trade_mtm`·`dailyPnl`·`dv`·`masked` 에만
들어가고(`mrbacktest.py:241,369`) z 는 `values` 에서 따로 난다. 거래 목록은
한 건도 안 움직인다.

### ⑤ 그런데 롤 비용이 **0 이었다** — 그게 이 결정의 핵심

비용은 진입 봉과 청산 봉에만 걸린다(`mrbacktest.py:354,421`). 분기마다 실제로
구계약을 정리하고 신계약에 들어가는데 그 왕복이 모형에 없다. 마스크가 그것을
가리고 있었다 — 롤일 돈을 통째로 0 으로 만들면 이득도 비용도 같이 사라진다.

**연결선물이라서 안 물어도 되는 것이 아니라, 연결선물이라서 물어야 한다**
[OWNER 2026-09-04]. 연결 계열은 데이터 구조물이지 상품이 아니다. 조정가가 빼는
것은 계약 사이의 **가격 단차**(캘린더 스프레드 수준)이지 그 갈아타기의
**마찰**이 아니다. 즉 조정가 차분의 손익은 «공짜로 롤했다고 가정한 포지션» 의
손익이고, 그 가정의 값이 롤 비용이다.

(모듈 머리의 「연결 계열의 롤오버 갭 병은 실측으로 없다」는 **가격 계열이
깨끗하다**는 말이지 **롤이 공짜**라는 말이 아니다. 다른 명제다.)

롤을 피하는 길이 더 비싸다는 것도 근거다: 롤 전 청산·롤 후 재진입은 편도
0.5bp 왕복이라 0.5틱 왕복보다 3배 비싸다. **0.5틱은 보수적인 값이 아니라 가장
싼 경로의 값이다.**

### ⑥ 결정 — 0.5틱 편도, 그리고 **bp 가 아니라 틱으로** 넣는다

    롤 비용(원) = 액면 / 100 × 0.01        # 왕복 1틱 = 0.5틱 편도 × 2

bp 로 박으면 안 된다. 1틱이 몇 bp 인지가 수준을 따라 움직이기 때문이다(실측:
3Y 표본 첫날 0.324bp → 끝날 0.350bp, 10Y 0.097 → 0.121bp). 고정 bp 는 6년에
걸쳐 8~25% 조용히 어긋난다. 액면이 이미 진입일 커브로 서 있으므로 위 식은
수준을 저절로 따라간다.

**자리는 비용 열이다.** 새 열을 만들지 않고 엔진 비용에 더한다 — 그래야
`그날 손익 = 평가 + 캐리 + 롤다운 + 조달 + 비용` 이 그대로 닫히고 대사표에 열이
하나 더 서지 않는다.

### ⑦ 수치 — 기본 노브(60일 · 2σ/0.5σ · 편도 0.5bp · 100만원/bp)

비용은 양쪽 다 뺀 값이다(노브지 상품의 성질이 아니다). 단위 백만원.

| 계열 | 거래 | 엔진 근사 | 실가격 | 그중 롤일 | 보유중 롤 | 롤 비용 | 실가격 − 롤비용 |
|---|---:|---:|---:|---:|---:|---:|---:|
| FUT-KTB3  | 58 | −57.5 | −45.0 | +9.0  | 19 | −6.29 | **−51.3** |

**부호는 안 뒤집힌다.** 롤 비용을 물리기 전 FSW-3Y 가 −19.8 → +5.3 으로 뒤집혀

### ⑧ 화면이 말해야 하는 것

롤일 행의 Δbp 는 계약 교체라 튄다(실측 KTB3 중앙 5.70bp·최대 27.2bp —
`futures.book_recon` 이 이미 「그건 사실이라 안 지운다」고 적어 둔 그 값).
그러면 `추정 = −KRD × Δbp` 가 통째로 유령이 되고 **잔차가 그것을 다 진다.**
표가 그 행에 이유를 적지 않으면 읽는 사람은 「대사가 깨졌다」고 읽는다.

## 대사표를 다리별로 — 국고 매수 · IRS 페이 (2026-09-04) [OWNER — «국고매수랑 IRS Pay가 별개로 뜨게 해줘»]

### 종전 표는 자가 섞여 있었다

- `krd` 는 `_krd_bond` 라 **국고 다리 것만**이었다(민평 노드 범프). IRS 다리의
  감도는 표에 아예 없었다.
- `dbp` 는 `asw_series` 라 **«민평 − IRS» 스프레드**였다.
- 그래서 `추정 = −(국고 KRD) × Δ스프레드` — par-par 자산스왑의 1차 근사로는
  성립하지만 **한 다리의 감도에 두 다리의 Δ** 를 곱한 자였고, 그 몫이 전부
  잔차로 갔다.

실측(2020-03-27~04-09 · BSS-7Y · 9봉): 03-31 행이 추정 535만에 잔차 137만(26%).

### 무엇을 했나

`cashbond.book_recon` 이 행마다 `legs: [국고, IRS]` 를 싣는다. 다리마다
KRD·Δbp·추정과 평가·캐리·롤다운·조달·그날 손익을 **자기 커브 위에서** 낸다.

- 국고 다리 — 민평 노드·Δ민평. 조달은 이쪽만 진다(현물을 조달해 들고 있다).
- IRS 다리 — IRS 노드·ΔIRS. 조달은 `None` 이다(0 이 아니라 «그 질문이 없다»).
- 스왑 KRD 는 `backtest.bumped_par_curve` 를 부른다 — 백테스트 표의 범프 루프를
  함수로 들어낸 것이고, KRD 의 정의가 두 곳에 서면 두 표가 같은 리스크를 다르게
  말한다.
- **스프레드 관점은 은퇴했다** [OWNER — «없앤다»]. 페이로드에는 남아 있어
  백테스트·시뮬 표가 종전 그대로 서지만, MR 화면은 다리 둘과 합계만 그린다.

### 잰 것

    Σ|잔차|   옛(국고 KRD × Δ스프레드)   1,992,450원
              새(다리마다 자기 커브)         63,770원   −96.8%

다리 합이 그날 손익과 **원 단위로 0** 이고, 다리마다
`평가+캐리+롤다운+조달 = 그날 손익` 이 0원, 칸마다 `−KRD × Δbp = 추정` 이다.
2020-03-30 실측: 국고 −3,699,662 · IRS +3,496,067 · 합 −203,595 = 그날 손익.
IRS 7Y KRD −1,003,434 가 국고 +976,460 을 상쇄한다(페이 고정 = 잔존에서 숏).

### 반올림 규율 — 총계가 정본이고 국고 다리가 잔차를 진다

다리마다 따로 반올림하면 다리합이 그날 손익과 갈린다(실측: 배수 1.48 에서
거래당 431만원 — `_mr_scale_rows` 가 리스트를 안 곱하고 있던 자리). 그래서
IRS 다리를 자기 값으로 세우고 **국고 다리를 «총계 − IRS»** 로 낸다.
다리 안에서는 `splitKrw` 와 같은 규칙으로 평가가 잔차를 진다.

### 밟은 함정

**IRS 계열의 Δ 를 민평 색인으로 읽었다.** 이 표의 행은 민평 달력의 하룻밤인데
IRS 종가는 자기 달력 위에 있다 — `imap[i]`·`imap[i-1]` 로 읽어야 같은 밤이 된다.
민평 색인을 그대로 넣었더니 **잔차가 6.4만에서 2,100만원으로 뛰었다**(330배).
값이 그럴듯하게 크기만 했다면 못 잡았을 텐데, 옛 잔차와 비교하는 줄을 검산에
같이 넣어 둬서 바로 보였다.

### 화면

`ReconStack` 이 다리 모드에서 하루 **일곱 줄**을 세운다: 다리마다 KRD·Δbp·손익
셋, 그리고 합계 한 줄. 날짜 칸이 일곱을, 다리 칸이 셋씩 덮는다. 왼쪽 고정 열이
셋이 됐다(날짜·다리·구분) — `<colgroup>` 트랙과 sticky 오프셋이 **같은 상수**를
곱한다. 합계 줄의 테너 칸은 비운다: 두 다리의 KRD 는 다른 커브에 실린 감도라
한 칸에 못 더한다(혼합 북 격자를 가른 것과 같은 근거).

열은 **두 다리의 합집합**이고 만기순으로 다시 세운다(`reconTenors`) — 그냥 이어
붙이면 IRS 전용 1D·4Y·6Y 가 민평의 30Y 뒤에 서서 커브가 왼쪽에서 오른쪽으로
길어진다는 이 표의 유일한 읽는 법이 깨진다.

## TOP 5 의 「채택」 열 고정 (2026-09-07 밤)

### 왜 폭으로는 못 닫는가

이 표의 열 폭은 **내용에서 온다** — 돈 문자열이 넓어지면 표도 넓어진다. 그래서
넘침이 계열마다 다르다(실측 BSS-3Y **10px** · FSW-3Y **47.7px**). 폭을 못 박아
닫으면 다른 계열에서 잘리고, 이 리포는 잘림을 금지한다(「말줄임 절대 금지」).
넘친 쪽이 하필 **누르는 칸**이라 표의 유일한 액션이 기본 화면에 없었다.

### 대사표 고정 열과 **같은 문법**

`.sr-mr-optgrid`(theme/type.css). `.sr-recon-stick`·`.sr-recon-edge-l` 의 규율
셋을 그대로 따른다: ①고정 셀의 배경은 불투명 ②경계는 **`box-shadow` 만**
(`border` 는 레이아웃을 1px 밀고 sticky 셀에서 그 1px 이 곧 샘이다) ③헤어라인이
「여기서부터 덮고 있다」를, 안쪽 옅은 그림자가 「밑을 지나간다」를 말한다.

⚠ **클래스를 따로 뒀다.** 상자 클래스(`.sr-mr-drawertable`)는 대사표와 공유라,
거기에 걸면 하루 일곱 줄짜리 대사표의 마지막 열까지 같이 붙는다.

### ★ 안 넘칠 때는 그림자를 안 그린다

덮는 것이 없는데 「덮고 있다」를 그리면 화면이 **없는 사실**을 말한다 —
`.sr-recon-div-l` 이 2026-09-03 에 같은 이유로 그림자를 버리고 헤어라인만 남긴
그 판단이다. CSS 는 넘침을 모르므로 `OptimizePane` 이 재서 `data-covering` 을
단다. 재는 자리는 **CDS 가 두른 `overflow-x:auto` 상자**다 — sticky 의 기준
컨테이너와 같은 상자를 재야 한다(바깥 Box 를 재면 늘 0 이라 그림자가 영영 안 선다).

### ⚠ ResizeObserver 하나에 안 기댄다 — 그리고 그건 검증 못 했다

RO 콜백은 **렌더 수명주기에 실려 온다**. 탭이 페인트를 안 하면 아예 안 오고,
브라우저 실측에서 정확히 그랬다(자동화 탭에서 콜백 **0회** — 이 리포가 rAF 에서
이미 겪은 그 인공산물). 그래서 `resize` 도 같이 듣는다.

**측정 논리 자체는 실측으로 확인했다** — 리렌더를 강제해 코드 경로로 통과시켰다:
넘침 10 → `covering=1` · 표를 좁혀 넘침 0 → `covering=0` · 되돌리면 다시 1.
**RO 로 촉발되는 경로만은 이 탭에서 확인 못 했다**(환경 탓이지 코드 탓이라는
증거는 없다). 다음 사람이 실제 브라우저에서 창을 줄여 보면 그 한 칸이 닫힌다.

### ★★★ 함정 먼저 — 「동일 액면」은 더 좋은 전략이 아니다

동일 액면 판(다리마다 같은 액면, DV01 을 조정)이 총손익을 5.87억 → **10.13억**
으로 냈다. 그런데 **총 DV01 이 900만 → 2,013만원/bp 로 2.24배**다. 같은
대차대조표에서 위험을 두 배 넘게 키운 것이다. **DV01 로 정규화하면 뒤집힌다:**

| | DV01당 손익 | DV01당 낙폭 | DV01당 액면 |
|---|---|---|---|
| A 동일 DV01(현행) | **6,526만** | **568만** | 9.8억 |
| B 동일 액면 | 5,030만 | 748만 | **4.1억** |

**B 는 위험당으로 A 보다 나쁘다**(손익 −23% · 낙폭 +32%). 대신 **같은 DV01 을
절반 이하의 대차대조표로** 낸다(9.8 → 4.1억). B 는 전략 개선이 아니라
**대차대조표를 DV01 로 바꾸는 거래**다. 그 구분을 안 하면 「손익이 두 배」라는
문장이 그대로 결론이 된다.

### 표본밖이 결론을 갈랐다

표본내에서는 **상위 3개(10Y+5Y+1.5Y)가 Calmar 2.18** 로 전체 9개(1.76)를 이겼다 —
다리를 빼는 것이 낙폭까지 개선하는 것처럼 보였다. **표본밖에서는 안 산다:**

| 뒤절반 | 총손익 | Calmar | 대차대조표당 | 유효N |
|---|---|---|---|---|
| **상위 9(전체)** | 2.70억 | **1.84** | 0.77% | 3.8 |
| 상위 7 | 1.75억 | 1.66 | 1.17% | 3.2 |
| 상위 5 | 0.74억 | 0.95 | 1.32% | 2.7 |
| 상위 3 | 0.66억 | 1.46 | **1.74%** | 2.2 |
| B 동일액면 | 3.59억 | 1.22 | 1.18% | 3.8 |

**낙폭 축에서는 전체 9개가 표본밖 1등이다.** 표본내 1등이던 상위 3개는
2.18 → 1.46 으로 떨어졌다 — **다리 빼기는 과적합**이었고, 오늘 만든 표본밖
검정이 없었으면 채택했을 것이다.

**대차대조표 축에서는 살아남는다** — 상위 3개가 뒤절반에서도 1.74% 대 0.77%
(2.3배). 앞절반 순위(10Y>5Y>1.5Y>7Y>3Y>2Y>1Y>9M>6M)가 전 표본 순위와 같았다.

### 그래서 답 — 구속이 정한다

- **낙폭이 구속이면 바꿀 게 없다.** 지금 구성(동일 DV01·9만기)이 표본내·표본밖
  모두 Calmar 1등이다.
- **대차대조표가 구속이면 두 길이고 성격이 다르다.**
  **다리 빼기**는 대차당 2.3배인데 **분산을 버린다**(유효 독립 3.8 → 2.2).
  **동일 액면**은 대차당 1.5배이고 **분산은 그대로**(3.8 유지) — 대신 DV01 이
  2.24배라 **한도가 받아 줘야 한다**(10Y 다리가 620만원/bp).

오너 상황(데스크는 대차대조표 구속 · 지금은 자유)에 놓으면: **당장 바꿀 이유는
없고**(자유로우면 낙폭 축이 맞고 거기선 현행이 최적), **데스크 제약 안으로 들어갈
때 쓸 손잡이가 동일 액면**이다. 다리 빼기는 표본밖에서 낙폭 축을 잃어 덜 매력적이다.
